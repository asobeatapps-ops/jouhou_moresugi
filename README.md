# 情報、漏れすぎ。 / ASOBEAT

安全なら「やる」。危険なら「やらない」。時間制限なく考えて選べます。会社の秘密を守る、1プレイ最大5問の判断ゲームです。全15エンディングと収集図鑑を備えた、サーバー不要の公開MVPです。

想定公開先：https://asobeatapps-ops.github.io/jouhou_moresugi/

## 遊び方

1. 「出勤する」で開始。画面上部のチャットで、左に部長、右に自分の発言が積み重なります。1メッセージ2秒で自動送りし、タップでも1つ進めます。初回8、再挑戦時2メッセージ。過去の発言はスクロールで読めます。
2. 文章を読み、安全なら「やる」、危険なら「やらない」を選びます。**選択の制限時間はなく、待つだけでは問題もスコアもミスも変わりません。**
3. PCはマウス、またはTabで選択してSpace／Enterで決定。「やる」は長押し・二度押しの隠し操作にも対応します。
4. 正解で得点とコンボが増えます。5問を答えると「勤務完了」。3ミス、または特殊ENDが成立した場合は途中で終了します。
5. 結果や図鑑から再挑戦。未発見カードには攻略ヒントがあります。

全30通常問題と特殊11問の中から、1プレイは最大5問です。「アクセス権」などの専門用語を避け、住所・電話番号・スマホの確認コードなど、具体的な行動で判断できる文章にしています。

5問目には保存された出勤回数に応じた9周期の特殊ルートを予約し、2問続くルートは4〜5問目に出します。通常問題は同一プレイ内で重複させず、安全・危険の両方を出し、同じ種類が3回続くことを防ぎます。通常END01〜05が5問以内で成立するよう、出勤ごとに安全・危険の比率を切り替えています。

5問を終えて3ミス未満なら「勤務完了」です。これは新しい図鑑ENDではなく、15種類の図鑑は維持します。真END15はEND01〜14を登録済みの状態で、新しい1プレイの5問すべてに正解すると成立します。5問目の隠し操作には400msの判定時間を残し、二度押しより先に勤務完了で閉じないようにしています。

## ローカル起動

```sh
python3 -m http.server 8020
```

http://localhost:8020/ を開きます。ES Modulesを利用するため、`file://`で直接開くのではなくHTTPサーバーかGitHub Pagesを利用してください。npmによるビルドや外部ライブラリの読み込みは不要です。

## ファイル構成

- `index.html`：タイトル・プレイ・END・図鑑の4画面
- `css/style.css`：スマホ中心のレイアウト、Safe Area、VFX、動きを減らす設定
- `js/data.js`：通常30問・特殊11問、15ENDとヒント
- `js/engine.js`：出題・進行・得点・操作競合・END優先順位
- `js/main.js`：DOM、入力、画面遷移、フォーカス管理・時間停止
- `js/art.js`：Canvasによるオフィス、人物、15種類のENDアニメーション
- `js/audio.js`：オリジナル生成BGM／SE、音声解除・停止
- `js/storage.js`：ブラウザ保存と失敗時のメモリ継続
- `assets/favicon.svg`：自作アイコン
- `privacy.html`：データ取り扱い
- `tests/`：外部依存のないNode.jsテスト
- `DEVELOPMENT_SPEC.md`：受領した承認済み仕様
- `QA_REPORT.md`：検証結果と未実施項目

## 判定・時間の設計

通常の選択に締切はありません。未選択のまま待つことと「やらない」を選ぶことは区別します。「やる」は指を離した時点、「やらない」はボタンの確定操作で1回だけ判定します。

5問版は正解1問100点、最大500点・5コンボです。旧版の点数計算関数も残していますが、6問目は出題しません。正誤判定は1回、判定待機400ms、各ENDアニメーション3000ms。真END→隠し→特殊→通常の優先順位で一度だけ確定し、どれにも該当しない5問回答後に勤務完了とします。

HS-01は「やる」を1500ms以上長押し、HS-02は「やる」の2回のタップを離した間隔が240ms以下の場合に成立します。これらは隠し操作専用の条件で、通常問題の選択期限ではありません。HS-02の1回目は通常判定し、400msの判定中に限って2回目の隠し操作を受け付けます。2回目は再採点しません。

問題ごとのトークンと単一ステートマシンで古い入力を無効化し、問題進行のsetTimeoutは使いません。会話にもメッセージ番号・出勤識別子を使い、自動送りとタップが重なったときの古い入力を無効化します。タブ移動・フォーカス喪失でプレイを停止し、再開ボタンで戻ります。回転・リサイズ・pointercancelでは押下状態を解除します。結果と図鑑は小さい画面で縦スクロールできます。

2人の肌は暖かい自然な色に統一し、濃い頬の影を除去しています。笑顔・自信・話し顔・驚き・困り顔・動揺などを会話と正誤で切り替えます。オフィス描画は縦横比を保ち、画面サイズで顔が縦長にならないようにしています。

## 保存・音声・プライバシー

`asobeat_jouhou_moresugi_v1` に発見END、自己ベスト、最大コンボ、音声設定、出勤回数、直近50回の結果を保存します。過去のベストと図鑑はそのまま引き継ぎます（旧版の記録は5問版の上限を超える場合があります）。勤務完了は履歴上のend:0で保存し、発見済みENDには追加しません。保存拒否・破損時もメモリ上で継続し、保存できない旨を表示します。リロード・端末間での引き継ぎはブラウザ保存の範囲に限られます。

Web Audioはユーザー操作で初めて作成・再開します。初期設定は音声ONで、右上から切り替えられます。BGMはミスに応じて音階と警告音が変化します。隠しタブでは停止し、使い終わった音声ノードを解放します。対応しない環境では無音で遊べます。

Firebase、外部API、解析、オンラインランキングは利用しません。結果画面だけに未有効の広告掲載予定枠を置いています。広告の配信・AdSense承認は本MVPの完成とは別です。問題文はゲームの設定で、実際の情報送信・削除・公開処理はありません。

## テスト

```sh
npm test
```

Node.js標準テストランナーのみを利用します。ブラウザ検証には開発依存のPlaywright 1.62.1を使用します。別ターミナルで上記HTTPサーバーを起動してから、`npm install`、`npx playwright install chromium webkit` を実行し、`npm run test:browser` / `npm run test:audio-browser` / `npm run test:keyboard` で再現できます。`/usr/bin/chromium` が存在する場合はそれを利用し、それ以外はPlaywrightの管理するChromiumを利用します。別の実行パスは `CHROMIUM_PATH`、サーバーURLは `GAME_TEST_URL`、出力先は `GAME_TEST_OUTPUT` で指定できます。PlaywrightのWebKitはSafari相当のエンジン検証であり、実機Safariそのものの検証ではありません。詳細はQA_REPORTを参照してください。実機での操作や音声の確認は自動ブラウザ検証とは区別しています。

## GitHub Pages

リポジトリの Settings → Pages → Build and deployment で、**Deploy from a branch / main / (root)** を選びます。`index.html`、`css/`、`js/`、`assets/`、`privacy.html`、`.nojekyll` をそのまま配信できます。サーバー、ビルド、鍵、料金が発生するAPIは不要です。
